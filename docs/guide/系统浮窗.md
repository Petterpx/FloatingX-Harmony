# 系统浮窗

系统模式创建独立原生浮窗，接收所属 `UIAbilityContext` 和正数 vp 尺寸。它不要求先建应用内 Host；仅显式选择降级时才需要 `FxWindowHost`。

## 权限与适用范围

消费者在 `src/main/module.json5` 的 `requestPermissions` 中声明：

```json5
"requestPermissions": [
  { "name": "ohos.permission.SYSTEM_FLOAT_WINDOW" }
]
```

声明不是授权。该权限受目标系统发行政策、签名和审批约束。库检查授权结果，不弹权限申请窗口，也不自动打开设置。

[华为 HarmonyOS 5.0 受限开放权限说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-v5/restricted-permissions-V5)将该权限列为 `system_grant`，限定可申请的 2in1 多人视频通话 / 屏幕共享场景，并要求浮窗提供退出方式。其他场景应按目标 SDK / 发行政策确认可用方案；不能把 Android 的权限申请流程照搬过来。

本仓库的 API 24 模拟器运行效果不能代表商业手机 / 平板可以取得系统授权。商业手机 / 平板系统权限、有商业授权的目标设备表现仍需验收。

## 完整创建函数

```ts
import common from '@ohos.app.ability.common';
import { FloatingX, FxContent, FxControl, FxConfig } from 'floatingx';

class SystemFloatParams {
  close: () => void;
  constructor(close: () => void) { this.close = close; }
}

@Builder
function systemFloatContent(params: SystemFloatParams) {
  Column() {
    Text('系统浮窗：拖动标题').height(40)
    Button('关闭').onClick(params.close)
  }.width(220).height(90).backgroundColor('#FFEACA').borderRadius(12)
}

export function createSystemFloat(context: common.UIAbilityContext): FxControl<SystemFloatParams> {
  let control: FxControl<SystemFloatParams> | undefined;
  const content = new FxContent(wrapBuilder(systemFloatContent),
    new SystemFloatParams(() => {
      if (control !== undefined) {
        control.cancel().catch((error: Error) => console.error(error.message));
      }
    }), { width: 220, height: 90 });
  control = FloatingX.installSystem({
    tag: 'system-player', context: context, content: content,
    size: { width: 220, height: 90 },
    config: new FxConfig({ position: { x: 20, y: 100 }, adsorb: false }),
    interactions: { dragArea: { x: 0, y: 0, width: 220, height: 40 } },
    events: (event) => {
      console.info('FloatingX scope=' + event.actualScope);
      if (event.error !== undefined) console.error(event.error.code);
    }
  });
  return control;
}
```

调用者持有该函数返回的控制器，在 `show()` 时捕获权限 / 能力 / 窗口错误。工厂本身也可能同步抛出参数或 tag 错误。`context` 应是业务所属 UIAbility 的上下文。

包含完整页面、上下文获取、关闭按钮和拥有者管理的例子：[SystemDemo.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/pages/SystemDemo.ets)。

## 显式应用内降级

默认不降级：未授权 `show()` reject `PERMISSION_DENIED`，能力不支持 reject `CAPABILITY_UNSUPPORTED`。

需要应用内降级时，在 `installSystem` options 中增加 `fallback: { host: host, pagePolicy: ... }`；`host` 按[应用内浮窗](应用内浮窗.md)创建，调用工厂时必须有效。完整带降级代码见 `SystemDemo.createSystemControl`。

仅系统创建时的权限 / 能力失败可以触发降级。事件的 `actualScope` 变为 `app`，同时以 ERROR 事件报告原始失败原因；`show()` 仍可能成功显示应用浮层，业务不要只看 Promise 成功就判断是系统窗口。其他窗口操作错误不会自动降级。

降级后遵守应用内 Host 的前后台、页面过滤和生命周期。存储键仍保留安装时的 system 作用范围，详见[位置存储](位置存储.md)。

## 隐藏与释放

API 12 没有公开原生窗口 hide 接口。系统模式的 `hide()` 隐藏内容、保留透明窗口并关闭触摸 / 焦点；`show()` 恢复，`cancel()` 才销毁窗口。

在目标设备检查透明窗口是否有阴影残留、触摸 / 焦点透传和跨应用显示行为。`DisplayOnly` 也会禁用浮窗内容交互，不能再依赖内容中的关闭按钮；应用需保留其他退出入口。

系统实例由业务拥有者显式管理，在所属 UIAbility / Stage 结束时取消。系统模式未降级时，销毁应用内 Host 不会代替取消系统浮窗。参考 [DemoOwner.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/entryability/DemoOwner.ets)以及 [EntryAbility.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/entryability/EntryAbility.ets)的系统拥有者清理。

系统窗口移动和尺寸更新等待平台确认；平台能力不足或操作无法确认时可能拒绝并终止实例。收到错误后检查 `getState()`，已终止实例需要重新创建，避免无限重试同一句柄。
