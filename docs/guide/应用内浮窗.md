# 应用内浮窗

应用内模式将浮窗放在一个已加载的主窗口浮层中，无需系统浮窗权限。它绑定单个 `WindowStage`，适合在同一主窗口的页面之间保留浮窗；进入后台时隐藏。

完整接入源文件：[EntryAbility.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/entryability/EntryAbility.ets)（创建 / 销毁 Host）与 [AppDemo.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/pages/AppDemo.ets)（参数类、Builder、等待 Host 就绪和页面通知）。

## 创建并持有 Host

必须等 `WindowStage.loadContent` 成功后创建 `FxWindowHost`。页面先被加载、Host 后就绪，所以示例使用 LocalStorage 的就绪标记通知页面。

下面是应用内模式需要的完整 Ability 生命周期代码；页面可按 `AppDemo.ets` 读取相同的 LocalStorage 键。

```ts
import UIAbility from '@ohos.app.ability.UIAbility';
import window from '@ohos.window';
import { FxWindowHost } from 'floatingx';

export default class EntryAbility extends UIAbility {
  private host?: FxWindowHost;
  private stageEpoch: number = 0;

  onWindowStageCreate(stage: window.WindowStage): void {
    const epoch = ++this.stageEpoch;
    const storage = new LocalStorage();
    storage.setOrCreate('fxHostReady', false);
    stage.loadContent('pages/Index', storage, (error) => {
      if (error.code || epoch !== this.stageEpoch) return;
      FxWindowHost.create(stage, () => epoch === this.stageEpoch)
        .then((host: FxWindowHost) => {
          if (epoch !== this.stageEpoch) {
            host.dispose().catch((failure: Error) => console.error(failure.message));
            return;
          }
          this.host = host;
          storage.setOrCreate('fxWindowHost', host);
          storage.setOrCreate('fxHostReady', true);
        })
        .catch((failure: Error) => console.error(failure.message));
    });
  }

  onWindowStageDestroy(): void {
    this.stageEpoch++;
    const host = this.host;
    this.host = undefined;
    if (host !== undefined) {
      host.dispose().catch((failure: Error) => console.error(failure.message));
    }
  }
}
```

创建 guard 防止 Stage 已销毁时异步创建结果迟到。`dispose()` 会同步使 Host 失效，并异步取消归属它的控制器及释放监听；保留和处理清理 Promise。

## 安装浮窗

以下完整函数定义内容参数与 Builder，接收上述创建的有效 Host。调用者持有返回的控制器，调用 `show()` 并处理 rejection，业务结束调用 `cancel()`。

```ts
import { FloatingX, FxWindowHost, FxContent, FxControl, FxConfig } from 'floatingx';

class AppFloatParams {
  close: () => void;
  constructor(close: () => void) { this.close = close; }
}

@Builder
function appFloatContent(params: AppFloatParams) {
  Column() {
    Text('拖动标题').height(40)
    Button('关闭').onClick(params.close)
  }.width(220).height(90).backgroundColor('#DDEEFF').borderRadius(12)
}

export function createAppFloat(host: FxWindowHost): FxControl<AppFloatParams> {
  let control: FxControl<AppFloatParams> | undefined;
  const content = new FxContent(wrapBuilder(appFloatContent),
    new AppFloatParams(() => {
      if (control !== undefined) {
        control.cancel().catch((error: Error) => console.error(error.message));
      }
    }), { width: 220, height: 90 });
  host.setPage('Home');
  control = FloatingX.installApp({
    tag: 'music', host: host, content: content,
    config: new FxConfig({ position: { x: 20, y: 120 }, adsorb: false }),
    pagePolicy: { mode: 'blacklist', names: ['Blocked'] },
    interactions: { dragArea: { x: 0, y: 0, width: 220, height: 40 } }
  });
  return control;
}
```

`tag` 在 app / system 间共享，不能重复。创建工厂同步抛错，用 `try/catch`；显示失败用 `.catch()` 或 `try/await`。多个实例完整例子见 [MultipleDemo.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/pages/MultipleDemo.ets)。

## 页面黑白名单

`pagePolicy` 默认是空黑名单，即允许所有页面。匹配的是业务给 Host 的页面字符串，不会自动解析 router 或 Navigation。

| 配置 | 显示规则 |
| --- | --- |
| `{ mode: 'blacklist', names: ['Blocked'] }` | 名称为 Blocked 时隐藏，其余允许 |
| `{ mode: 'whitelist', names: ['Home', 'Player'] }` | 仅 Home / Player 允许，未知页面隐藏 |

router 页面出现时、Navigation destination 的 `onShown` 中调用 `host.setPage(name)`，返回上一页也要恢复对应名字。参考 [FilteredPage.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/pages/FilteredPage.ets)与 `AppDemo` 的 `destination` / `onNavBarStateChange`。

页面过滤和后台隐藏会保留显示意图，重新允许 / 回到前台时恢复。主动 `hide()` 则清除显示意图，需要再次 `show()`。

## 生命周期与层级

业务可以让控制器由页面持有，也可以由更长生命周期的业务服务持有。`AppDemo` 为演示页面拥有：页面退出就取消。要跨 router 页面继续显示，应把控制器交给 Stage 级拥有者，避免在原页面消失时取消。

不要在 Stage 结束后复用 Host。多个 WindowStage 各自创建 Host，并使用不重复的 tag；跨窗口状态移交由应用管理。

浮层尚未测量时，`show()` 可以接受意图但暂不显示，完成布局后恢复。应用内浮层的 Dialog 层级、空白区域透传和安全区行为应在目标设备实际检查；完整示例提供原生 Dialog 和底层按钮供观察。
