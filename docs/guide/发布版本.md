# 发布与下载

[GitHub Releases](https://github.com/Petterpx/FloatingX-Harmony/releases) 提供每个版本的四项附件：

| 附件 | 用途 |
| --- | --- |
| `floatingx-vX.Y.Z.har` | 源码 HAR，复制到消费模块的 `libs/floatingx.har` 后使用本地依赖接入 |
| `floatingx-demo-vX.Y.Z-openharmony-api12-unsigned.hap` | 官方 OpenHarmony API 12 SDK 编译的未签名示例包 |
| `SHA256SUMS` | HAR、HAP 和 manifest 的 SHA-256 校验值 |
| `manifest.json` | 标签、源码提交、构建工具提交、SDK、工具版本与产物校验值 |

HAR 的安装见[快速开始](快速开始.md)。示例 HAP **未签名**，不是可直接安装的商业 HarmonyOS 手机 / 平板包。需要在 DevEco Studio 使用目标设备配套的 HarmonyOS SDK、自己的应用标识与签名配置构建示例；系统浮窗还受目标平台的权限限制。

下载附件后，可在同一目录验证：

```sh
shasum -a 256 -c SHA256SUMS
```

## 维护者发布

1. 将待发布代码和 Release 工作流合入 `main`。
2. 为确定的提交创建标签并推送，格式为 `vX.Y.Z` 或 `vX.Y.Z-rc.1` 等预发布标签。
3. 在 GitHub 创建该标签的 Release 并点击 **Publish release**。预发布版本勾选 **Set as a pre-release**。
4. 查看 Actions 中的 **Release assets**；成功后四项附件会自动上传至该 Release。

工作流针对标签的确切提交运行核心测试，并用固定的官方 API 12 SDK 构建 HAR 和未签名示例 HAP。版本从标签派生，仅写入隔离的构建目录。主工程仍使用 HarmonyOS、phone / tablet 和最低 API 12 配置。

构建失败时，在 Actions → **Release assets** → **Run workflow** 中选择含工具修复的分支，填写已发布的原标签补跑。对应 Release 必须已经存在且已发布。源码始终来自填写的标签；manifest 分别记录源码和工作流工具的提交。请保留已发布标签的位置：补跑允许更新同一源码提交的附件，拒绝用不同提交覆盖已有产物。新代码应发布新标签。

工具和 SDK 版本统一维护在 `scripts/ci/toolchain.json`，Hvigor 依赖同时固定在 `scripts/ci/package.json` 与 `package-lock.json`。升级时验证官方归档的 SHA-256，并在受支持的 macOS arm64 环境运行同一构建脚本。
