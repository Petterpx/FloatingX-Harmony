# 常见问题

## 是否已经发布到 OHPM？

尚未发布。使用本地 `floatingx.har` 和 `file:` 依赖，步骤见[快速开始](快速开始.md)。消费应用只从 `floatingx` 导入公开 API。

## 选择局部、应用内还是系统？

局部显示在组件宿主范围内；应用内显示在单个主窗口浮层；系统创建独立原生窗口且受平台权限约束。前两种不需要系统浮窗权限，多数页面工具或应用内播放器可优先使用它们。

## show 成功，为什么没有看到浮窗？

成功可能表示已接受显示意图。检查：

1. scope 的 `FloatingXHost` 是否已挂载并具有正数布局尺寸。
2. app 是否使用 loadContent 完成后创建的有效 Host，是否已完成浮层布局。
3. app 是否在前台，页面名字是否被 `pagePolicy` 允许；白名单里的未知页面会隐藏。
4. 是否主动调用过 `hide()`；主动隐藏后需要再次 `show()`。

用 `isShow()` 和 SHOW / HIDE 事件判断实际可见，而不是只看 Promise 成功或 ATTACH。

## @Entry 页面根节点报错怎么办？

ArkUI 的入口页面需要容器根节点。用 `Stack` / `Column` 包住 `FloatingXHost`，不要让自定义 Host 成为 `@Entry` 页面直接根节点。完整写法见[快速开始](快速开始.md)。

## 浮窗里的按钮无法点击？

未配置 `dragArea` 时整个浮窗覆盖拖动 / 点击区域，可能拦截子按钮。将 `dragArea` 限定到标题，按钮放在区外。检查是否用了 `DisplayOnly`，该模式会禁用内容按钮和交互回调。

`onClick` / `onLongPress` 是库拖动区域的回调，区外按钮用自己的 ArkUI `onClick`。

## 取消后能否重新显示？

不能。`cancel()` 幂等地结束当前实例，后续修改 reject `DESTROYED`。再次显示请重新创建。局部 Host 的临时卸载 / 重挂可以复用控制器；不要为暂时隐藏而取消。

## 重复 tag 会自动替换吗？

不会。app / system 共享 tag 命名空间，重复同步抛 `DUPLICATE_TAG`。确需替换时先 `await FloatingX.uninstall(tag)`，再安装新实例。通常业务持有自己的控制器并取消，避免卸载其他业务的同名实例。

## 按 tag 找到的控制器为什么没有 updateContent？

`control()` / `controlOrNull()` 返回 `FxControlHandle`，没有内容参数类型。保留工厂的 `FxControl<T>` 才能调用 `updateContent(params: T)`。无实例时 `controlOrNull()` 返回 `undefined`，不是 null。

## updateConfig 改 gravity，为什么位置没变化？

gravity / offset 是初始定位参数，运行中的位置保留并受新边界限制。运行期移动用 `move()` / `moveByVector()`；需要重新按九宫格初始化则取消并重建，且 `position` 应为 undefined。

`updateConfig` 接收完整配置，新建 `FxConfig` 中未填的项使用默认值；若只想改一项，复制或保留自己的完整配置再提交。

## 保存位置后重建没有恢复？

存储默认关闭。检查同一业务是否复用了 namespace 和 key / tag。`FxMemoryStorage` 每个对象的记录独立，重建时新建 storage 会丢掉旧对象的内存记录；跨进程恢复使用 `FxPreferencesStorage`。见[位置存储](位置存储.md)。

## 系统权限应该 requestPermissionsFromUser 吗？

库使用的 `SYSTEM_FLOAT_WINDOW` 是受限系统授权权限，不提供 Android 式授权弹窗。宿主须按目标 HarmonyOS 版本、设备和发行政策办理授权。仅在 module.json5 声明不能保证可用，见[系统浮窗](系统浮窗.md)。

## 系统 show 失败会自动变成应用内浮窗吗？

默认不会。显式提供有效 `fallback.host` 才在系统创建遇到权限 / 能力错误时尝试降级。监听事件 `actualScope` 和 `error` 判断结果；其他窗口错误不会自动降级。

## 系统 hide 为什么还保留窗口？

API 12 没有公开原生 hide 窗口接口。库隐藏内容，保持透明窗口，关闭触摸 / 焦点；彻底释放需 `cancel()`。透明窗口的残留阴影、跨应用透传和焦点表现需在目标设备确认。

## 能否覆盖多 WindowStage、自动跟随所有页面？

应用内 Host 只绑定一个 WindowStage。多窗口分别创建 Host 并选不同 tag。router / Navigation 页面需要业务调用 `host.setPage(name)`；库不会自动识别页面。浮窗跨页生命周期由控制器拥有者决定，详见[应用内浮窗](应用内浮窗.md)。

## 动画或窗口操作失败怎么排查？

捕获 Promise rejection，并记录 `FxError.code` / `platformCode`。业务可通过 `FloatingX.setLogger()` 为之后创建的控制器设置日志；事件有 ERROR 和实际作用范围。清理失败要处理，不要无限复用已终止控制器。见[API 速查](API-速查.md)。

提交 [Issue](https://github.com/Petterpx/FloatingX-Harmony/issues)时提供最小复现、目标 SDK / 设备 / 系统版本、作用范围、配置和错误码。分享日志前去除业务数据和凭证。

## 模拟器 GIF 是否表示所有设备都可用？

GIF 来自 API 24 模拟器的真实示例操作，仅说明对应画面效果。API 12 真机、平板、有商业授权的系统窗口、键盘 / 旋转 / 安全区等目标场景仍需实际设备确认，不能从最低兼容版本或模拟器外推。
