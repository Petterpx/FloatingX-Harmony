# 局部浮窗

局部浮窗显示在 `FloatingXHost` 的布局范围内，坐标相对于宿主内容区，单位为 vp。它适合组件内浮动工具和局部悬浮按钮，不注册全局 tag，也无需系统权限。

## 接入

[快速开始](快速开始.md)提供包含 import、参数类、Builder 和页面生命周期的完整最小代码。更完整的能力演示见 [ScopeDemo.ets](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/pages/ScopeDemo.ets)。

创建时传入 `content`、`config`，按需要增加 `interactions`、`events` 和 `storage`。将工厂返回的控制器交给一个 `FloatingXHost`；同一个实例不要同时绑定多个宿主。

```ts
FloatingXHost({
  control: this.control,
  host: () => { this.hostContent(); }
}).layoutWeight(1)
```

这段布局使用完整示例中定义的 `control` 和 `hostContent`，应放在具有明确尺寸的父布局内。浮窗超出宿主的部分会被裁剪。

## 生命周期

| 操作 | 结果 |
| --- | --- |
| `show()` | 保存显示意图；宿主可用时显示 |
| `hide()` | 主动隐藏并清除显示意图 |
| 临时卸载 Host | 隐藏并 detach，显示意图保留 |
| 重挂原控制器 | 完成布局后按原意图恢复 |
| `cancel()` | 终止实例并释放资源，不能重新显示 |

宿主尚未挂载时可以调用 `show()`，Promise 可成功但 `isShow()` 仍为 false。不要将 Host 的临时卸载当成业务结束，也不要把 `ATTACH` 当作 `SHOW`。

页面退出时应取消页面拥有的控制器；需要跨局部宿主保留的控制器应交给更长生命周期的业务拥有者管理。完整示例会区分临时卸载与页面退出。

## 内容与交互

保留工厂返回的 `FxControl<参数类>`，通过 `updateContent(新参数)` 更新内容。异步成功表示参数已提交，ArkUI 布局和绘制随后完成。

为带按钮的浮窗指定标题 `dragArea`，给子按钮保留原生点击区域。坐标从内容左上角计算，宽高必须为正数，详见[配置与交互](配置与交互.md)。

## 初始定位与重建

`position` 优先于 `gravity`，`(0, 0)` 是有效坐标。`gravity` 定义初始位置；如果需要重新按九宫格定位，先取消旧实例，再用 `position: undefined` 与新的 `gravity` 创建。示例中的九宫格按钮使用这种方式。运行中的位置调整使用 `move()` / `moveByVector()`。

重新绑定不同控制器时，创建新的 Host 组件实例，避免旧宿主继续持有旧控制器。`ScopeDemo` 通过组件实例 key 完成重建，业务有快速重建 / 退出操作时可参考其 [DemoPageOwner](https://github.com/Petterpx/FloatingX-Harmony/blob/main/entry/src/main/ets/entryability/DemoOwner.ets)清理方式。
